# Обходы — автономное Android-приложение и конструктор маршрутов

**Отдельный самостоятельный проект. Не имеет связей с ТОиР или другими системами.**

## Состав

- `android/` — Kotlin + Jetpack Compose: загрузка маршрутов, проверки, сохранение результатов на телефоне в SQLite, ручная синхронизация.
- `backend/` — FastAPI, SQLAlchemy, API для маршрутов и результатов, русскоязычная веб-страница конструктора.
- `docker-compose.yml` — отдельная PostgreSQL + API.
- `.github/workflows/android-apk.yml` — сборка APK в GitHub Actions.
- `.github/workflows/backend-tests.yml` — автоматическая проверка backend.

## Как разместить в GitHub

1. Создайте на GitHub **пустой репозиторий** `obhody-app` (можно Private), без автоматического README.
2. Распакуйте архив на ПК, откройте терминал в папке `obhody-app`.
3. Выполните (подставьте свой GitHub username):

```sh
git init
git add .
git commit -m "Initial standalone inspections app"
git branch -M main
git remote add origin https://github.com/USERNAME/obhody-app.git
git push -u origin main
```

4. Откройте вкладку **Actions → Build Android APK → Run workflow**, дождитесь успешной сборки.
5. Откройте завершённый запуск и скачайте `Obhody-debug-APK` из **Artifacts**. Распакуйте архив, внутри `app-debug.apk`.

GitHub Actions собирает **отладочный APK для тестов**, не подписанный релизный APK для магазина приложений.

## Сервер с PostgreSQL

На ПК или VPS с Docker:

```sh
cp .env.example .env
# Обязательно замените POSTGRES_PASSWORD и API_TOKEN в .env на сильные случайные секреты.
docker compose up -d --build
```

Панель доступна на `http://localhost:8000`, API-документация — `http://localhost:8000/docs`. Введите в панели токен `API_TOKEN` из `.env`. Создайте маршрут, контрольные точки и вопросы.

**Важно:** по умолчанию API слушает только `127.0.0.1:8000` на сервере. Для доступа с телефонов настройте отдельный HTTPS reverse proxy (Caddy/Nginx), домен, TLS и сетевые правила. Не открывайте PostgreSQL в интернет и не используйте HTTP при эксплуатации. В локальной отладке эмулятор Android может обращаться к `http://10.0.2.2:8000` (если API работает на компьютере с эмулятором).

## Проверка API без Docker (SQLite)

```sh
cd backend
python -m venv .venv
# Linux/macOS: source .venv/bin/activate
# Windows: .venv\\Scripts\\activate
pip install -r requirements.txt pytest httpx
export API_TOKEN=local-test-token  # Windows PowerShell: $env:API_TOKEN="local-test-token"
uvicorn app:app --reload
pytest -q
```

## Что уже работает

- Веб-создание маршрутов, контрольных точек, четырёх типов вопросов (статус, число, текст, список вариантов).
- Отключение маршрута без удаления истории.
- Android: загрузка маршрутов и кеширование, заполнение, обязательные ответы, сохранение в SQLite, ручная отправка.
- Сервер: защита общим API-ключом, сохранение в PostgreSQL, повторные отправки по UUID не создают дубли, сохранение снимка маршрута в результате.
- Журнал результатов в веб-панели.

## Ограничения прототипа v0.2

- Это **GitHub-ready исходный проект**, а не уже собранный APK. Сборка Android проверяется в GitHub Actions после загрузки.
- Нет персональных учётных записей и ролей: общий API-ключ — только временное решение для закрытого тестирования.
- Нет полноценного расписания, QR/NFC, фотографий, редактирования существующих маршрутов, автоматического фонового обмена и защищённого хранилища ключей.
- Обходы можно выполнять повторно; назначение и контроль сроков не реализованы.
- Фото/файлы и персональные данные в таком виде для реальной промышленной эксплуатации не предусмотрены.
- Изменения структуры существующих маршрутов выполняйте созданием нового маршрута, старый можно отключить.

Следующая стадия перед продуктивным использованием: персональная авторизация, права доступа, миграции БД, резервное копирование, логирование, аудит, HTTPS-деплой, очередь автоматической синхронизации, интеграционное тестирование на реальных телефонах.
